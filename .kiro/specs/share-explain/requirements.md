# Requirements: share-explain (Feature C)

1. The Séance viewer SHALL encode a loaded trace file (`{ schemaVersion, trace }`) into a compact URL fragment `#t=<payload>`, and decode it back to an identical trace file (round-trip equality).
2. The payload SHALL be `z.<base64url>` (UTF-8 JSON compressed with `deflate-raw` via `CompressionStream`) or, when compression is unavailable or disabled, `p.<base64url>` (uncompressed). Only URL-safe characters SHALL be used.
3. On startup, if the URL has a `#t=` fragment (even empty or malformed), the viewer SHALL treat it as a share link: it wins over `?example=` and `?whatif=`, which are then ignored. A valid payload loads through the normal load path; an invalid, empty or malformed one SHALL show an error and SHALL NOT load a sample. `?example=` is used only when no `#t=` is present. The choice is made by the pure helper `selectStartup(search, hash)`.
4. A decoded trace SHALL always go through chain verification. A link whose trace was tampered with SHALL load and show the broken-chain badge; decoding SHALL NOT trust or skip verification.
5. Malformed links (unknown format, bad base64url, corrupt compressed data, invalid UTF-8, not a valid trace) and oversized links (payload over `MAX_PAYLOAD_CHARS`, or decoded data over `MAX_DECODED_BYTES`, including decompression bombs) SHALL be rejected with a clear message in the existing error box. Encoding SHALL reject trace JSON over `MAX_DECODED_BYTES` before compressing, and a payload over `MAX_PAYLOAD_CHARS`, with a message suggesting a trace file export.
5a. When `CompressionStream` is missing or does not support `deflate-raw`, encoding SHALL fall back to plain (`p.`) payloads instead of failing. Opening a `z.` link where decompression is unsupported SHALL show a clear error.
6. The viewer SHALL provide a "Copy share link" button, enabled once a trace is loaded, that copies the current URL with `#t=<payload>` to the clipboard and confirms or reports failure.
7. Sharing SHALL use no network access and no server.
8. A pure function `explainRun(trace, verifyResult)` SHALL produce a plain-English story: an intro (agent, version, step count, seed), one sentence per step (step number, time, which rule fired or that the fallback decided, the reason, the action), and a closing line stating whether the hash chain verifies.
9. For a broken chain the closing line SHALL say the chain is BROKEN, give the first broken step (1-based) and the reason when known, and warn that the trace must not be trusted.
10. The explanation SHALL be deterministic: the same trace and verify result always give the same text, and it SHALL mention every step and every rule id that fired.
11. The explain logic SHALL live in `packages/core/src/explain.ts` with no imports (browser-safe), be re-exported for the viewer from `viewer/src/explainRun.ts`, and be used by both the viewer and the CLI.
12. The viewer SHALL show the story in a collapsible "Explain this run" panel, rendered with `textContent` (trace content is untrusted), updated once chain verification completes.
15. Because share links auto-load untrusted traces, every trace-controlled value placed into `innerHTML` (badge, timeline, step detail, JSON blocks, hashes, what-if cards) SHALL be escaped with the pure `escapeHtml`/`escapeJson` helpers, which escape `& < > " ' \``; other trace text SHALL use `textContent`. Rendering SHALL NOT throw on out-of-range `timeMs`.
13. `npm run explain -- <trace.json>` SHALL print the story for an exported trace file or a bare trace. Exit code: 0 chain verifies, 1 chain broken, 2 usage or unreadable/invalid input.
14. All demo data remains synthetic and labelled EXAMPLE.
16. Composition with Tamper/Exorcise and the live what-if editor: a share link SHALL encode exactly the displayed recorded trace (`shareableFile(state.trace)`), so after Tamper it carries that exact tampered run (opening with the broken badge and a BROKEN story) and after Exorcise the restored run. Live what-if edits and scenario selections are overlays, SHALL NOT be shared, and SHALL NOT change the shared file or the story. The story SHALL refresh after load, Tamper and Exorcise, and SHALL only be rendered with the verification result of the same trace instance (stale async results are ignored). If the loaded file was already broken, Exorcise restores it as loaded.
